# ADR-004: 태그 기반 버전과 로컬 릴리스

상태: 채택. 결정일: 2026-09-28.

## 배경

기존 도구는 ZIP·DMG만 만들고 버전 갱신, 릴리스 본문, 태그·첨부 파일 게시를 수동 작업으로 남겼다. 앱의 업데이트 확인도 실제 GitHub Release가 있어야 동작한다. 원격 CI 없이 로컬에서 검증부터 게시까지 재현할 수 있는 명령이 필요하다.

## 결정

Plateau의 로컬 릴리스 운영 방식인 태그 기반 패치 버전, 명시적인 mise 게시 명령, 한국어 커밋 범위 노트, 다운로드 체크섬을 이 앱의 Swift·AppKit 번들에 맞춰 구현한다. 다른 프로젝트의 제품 코드·화면·내부 자료는 포함하지 않는다.

- 버전은 대상 커밋의 첫 번째 부모 계보에 있는 정식 `vX.Y.Z` 태그로 계산한다. 최초 버전만 대상 커밋의 Info.plist 값을 사용한다.
- 빌드 번호와 Git 커밋을 서명할 앱 복사본에 기록한다. 추적 중인 plist를 빌드가 수정하지 않는다.
- macOS 14 이상 Apple Silicon용 arm64 앱을 ZIP·DMG로 배포한다. CLI 설치용 PKG나 사용하지 않는 Intel 바이너리는 추가하지 않는다.
- 전체 검사, 실제 패키지 검사, 한국어 노트 생성이 끝난 뒤 태그·초안을 만든다. 첨부 파일을 다시 내려받아 검증한 후 공개한다.
- 일반 커밋·푸시와 릴리스는 분리한다. GitHub Actions, Git 훅, PR 자동화는 추가하지 않는다.
- 공개된 버전의 태그·파일은 보존한다. 중단된 초안은 같은 파일로만 재개한다.

## 결과

`release-plan`, `release-prepare`, `release`로 조회, 로컬 검증, 게시를 각각 실행할 수 있다. 실제 버전·커밋·아키텍처·서명 상태와 SHA-256을 manifest에 기록하여 앱·태그·파일명의 불일치를 거부한다. 한국어 커밋 제목의 Markdown 구두점은 표시용으로 이스케이프한다.

서명·공증은 자격 증명이 준비된 유지관리자의 Mac에서만 수행한다. 자격 증명이 없으면 ad-hoc 결과를 명확히 표시한다. Python 3 표준 라이브러리는 개발·릴리스 도구에만 필요하며 배포 앱에 추가하지 않는다. 실행 명령과 실패 복구는 [배포 안내](../releasing.md)를 따른다.
