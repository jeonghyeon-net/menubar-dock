# 1.0.1 동작 재구성과 검증

2026-09-28 · macOS 27.0 · Apple Silicon · Swift 6.4 / Command Line Tools.

## 바꾼 동작

이전의 합성 이미지 버튼과 단일 상태 항목 안의 자식 버튼은 모두 폐기했다. [원본 조사](../upstream-audit.md)를 다시 수행하고 앱별 `NSStatusItem` / 표준 `NSStatusBarButton` / `leftMouseUp` action 구조로 재작성했다. 기본 아이콘 40pt와 슬롯 30pt도 원본과 맞췄다. 상단에는 앱 아이콘만 있고 별도의 관리 아이콘이나 문자는 없다.

실행 요청은 신규·기존 앱 모두 `NSWorkspace.openApplication(activates: true)` 한 경로로 전달한다. 별도 비활성 reopen 뒤 activate 요청을 붙이던 경로를 제거했다. 설정은 너비 520pt, 탭별 높이 230–360pt인 창으로 구성하고, 앱 재실행 또는 선택 패널의 톱니 버튼에서 연다. 선택 패널은 재질 자체에 둥근 마스크를 적용한다.

입력 검증은 [check-status-input.sh](../../scripts/check-status-input.sh)로 재현한다. production UI 소스를 직접 컴파일하며 외부 앱을 실행하는 경계만 기록기로 바꾼다. 단순 target/action 호출만으로 클릭 성공을 판단하지 않는다. Swift Testing의 async main 안에서 AppKit 버튼 추적 루프가 프로세스를 조기 종료할 수 있어 별도 동기 실행 루프를 사용한다. 로그인된 macOS GUI 세션이 필요하다.

## 이미지와 확인 범위

- `settings.png`, `switcher.png`는 실행한 앱 창의 캡처다.
- `menu-bar.png`는 입력 검사에서 시스템 버튼을 각각 렌더해 나란히 배치한 참고 이미지다. 실제 메뉴 막대 간격이나 다른 디스플레이 합성 결과를 보여 주는 스크린샷은 아니다.
- 실제 앱 선택 패널의 왼쪽 클릭으로 시스템 설정과 Ollaya가 활성화되는 것을 확인했다. Ollaya 선택 후 frontmost bundle ID는 `dev.ollaya.app`이고 해당 구간 앱 실패 로그는 없었다.
- 사용자가 본 “사용할 수 없음” 창의 정확한 소유 앱·오류 문구는 확보하지 못했다. 실행 실패 로그에서 같은 오류를 재현하지 못했으며, 이를 해결됐다고 단정하지 않는다. 이후 오류는 OS 오류 domain/code를 기록한다.
- 물리적 두 화면의 비활성 외관, 로그인 재부팅, macOS 14–26 각 실기기, 장시간 사용은 추가 확인 범위다. 현재 로컬 패키지는 ad-hoc 서명이다.

GitHub Actions workflow를 제거하고 저장소 Actions도 비활성화했다. 검증은 `mise run check`, `mise run input-check`, `mise run smoke` 등 로컬 명령으로 수행한다.
