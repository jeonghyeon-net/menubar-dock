# 실행 앱 표시와 고정 해제 검증

## 재현과 원인

- 실제 설정에서 실행 앱 자동 표시는 켜져 있었고, 메뉴 막대 표시 한도는 4개였다.
- `WorkspaceMonitor`의 실제 스냅샷을 `WorkspaceCatalogReconciler`와 `DockCatalog.visibleItems`에 전달한 읽기 전용 검사에서 미등록 실행 앱 3개 중 3개가 누락됐다. 모두 기존 `removedApps` 기록과 일치했다.
- 기존 제거 명령은 고정 해제와 자동 감지 차단을 함께 수행했다. 사용자에게 확인한 현재 계약은 **고정만 해제하고 실행 중이면 표시**다.
- 실제 AppKit 하네스에서 Finder 제거를 요청했는데 미리보기의 슬롯이 삭제되는 실패를 재현했다. 마지막 슬롯 번호로 제거하던 경로를 앱 ID 기준으로 바꿨다.
- 슬롯 번호와 실제 좌우 순서가 다른 상태에서 좌표를 일시적으로 읽지 못하면 이미지가 재배정되는 실패도 재현했다. 마지막 유효 순서를 유지하도록 수정했다.
- 고정 해제한 앱을 종료 후 옮기고 바로 다시 등록하면 새 ID가 생겨, 늦은 bookmark 복구 후 예전 위치로 돌아가는 실패를 재현했다. 명시적 등록 전에 복사본에서 기존 bookmark를 복구하도록 수정했다.

## 동작 계약

- 설정의 `−`와 아이콘 메뉴의 **목록에서 제거**는 등록 목록에서만 제거한다.
- 자동 표시가 켜져 있으면 실행 중인 미등록 앱은 앞쪽에 남고, 종료하면 사라진다. 등록 앱의 상대 순서는 유지한다.
- 이전 삭제 기록도 실행 앱 감지를 막지 않는다. 저장 필드 `removedApps`는 Dock이 해당 앱을 다시 고정하지 않게 하는 용도로 유지한다.
- 아이콘 메뉴는 **목록에 추가/목록에서 제거 → 설정 → 종료** 순서다. 미등록 앱에는 추가만 제공하며 구분선과 단축키 표시는 없다.

## 검증 방법

- 도메인·저장·조립 테스트: 고정 해제, 종료·재실행, 이전 설정 복원, Dock 동기화, 이동한 앱의 ID와 순서 보존.
- 실제 AppKit 입력 검사: 우클릭·Control-클릭 메뉴, 설정 열기, 왼쪽 클릭, 슬롯의 추가·제거와 이미지 배정.
- 설치 검사: `/Applications`의 새 번들 서명·커밋·단독 실행, 등록 앱 순서와 사용자 설정 보존, 실제 실행 앱 스냅샷의 표시 누락 여부.

## 확인 결과

- 같은 사용자 설정과 실제 실행 스냅샷으로 다시 검사해 미등록 실행 앱 **3개 중 3개 표시, 누락 0개**를 확인했다. 임시 그룹 우선 배치, ID 중복 없음, 등록 순서 유지, 실행 ID가 비었을 때 임시 앱 숨김도 통과했다.
- 실제 슬롯 제거·첫/중간/끝 항목·좌표 누락 및 복구·번호 재사용·빈 목록·표시 한도 변경 검사를 통과했다. 네이티브 입력 하네스에서 왼쪽 클릭, 우클릭, Control-클릭, 설정 명령도 통과했다.
- 이동 후 재등록 회귀에서 원래 ID 재사용·목록 끝 배치·자동 고정 억제 해제·늦은 관찰 및 재시작 후 순서 유지·실패 시 원본 보존을 확인했다.
- Swift 테스트 199개와 릴리스 도구 테스트 78개를 통과했다. AppKit 포커스를 공유하는 UI suite는 명시적으로 직렬 실행하며, UI 68개의 완료와 실패 0개를 XML 결과로 확인했다.
- 배포 재검사에서 검색 입력의 고정 150ms 대기 후 요청 수가 0인 실패가 발생했다. 당시 입력 상태 기록이 없어 정확한 지연 원인은 확정하지 않았다. 제품 코드는 유지하고, 네이티브 하네스가 창의 입력 준비와 정확한 검색 요청 도착을 최대 2초 확인하도록 바꿨다. 이 하네스의 앱 검색·방향키·Enter·Escape·한글 조합 검사를 통과했다.
