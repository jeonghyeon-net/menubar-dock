# 선택 패널의 Spotlight 검색 검증

2026-09-28 · Apple Silicon Mac · macOS 27 · Swift 6.2 이상 도구 체인.

## 범위

Option+Tab 패널에 네이티브 검색 입력을 추가했다. 검색어가 없으면 기존 앱 선택을 유지하고, 입력하면 macOS Spotlight 인덱스에서 앱·파일·폴더의 이름을 찾는다. 별도 색인·외부 서비스·검색 기록 저장은 추가하지 않았다.

| 검사 | 결과 |
| --- | --- |
| `mise run check` | strict Swift 빌드, Swift 테스트 170개, 릴리스 도구 테스트 78개 통과 |
| 실제 검색 | 자체 생성한 합성 파일·앱·폴더를 OS 인덱스에 넣어 production 서비스로 조회. 한 단어·여러 단어·따옴표·별표·물음표·분음부호 검색과 조회 취소 확인 후 자료 정리 |
| 대량 결과 | 앞의 300개가 무효인 경우 뒤의 정상 결과, 400개 파일 뒤의 정확히 일치하는 앱을 찾음. 32개씩 처리하며 입력·취소에 실행 기회를 돌려주고 상위 50개만 유지 |
| 실제 AppKit 입력 | 문자 키 이벤트, 결과 갱신 중 field editor·포커스 유지, 결과 아래 빈 곳 클릭, 좌우 커서, 위·아래 선택, Enter·Esc, Option+Tab 중복 방지 통과 |
| 한글 | marked text 조합 중 실행·조회 보류, 실제 Enter로 조합 확정 후 검색 시작 확인 |
| 비동기 경계 | 검색어 변경·창 닫기·같은 검색어로 다시 열기 뒤 이전 응답 차단, 선택 보존, 조회 잠금 해제와 취소 확인 |
| 결과 열기 | 같은 결과의 연타는 합치되 서로 다른 결과는 별도로 실행. 사라진 경로·종류 변경·앱 ID 변경·열기 실패를 OS 경계 대역으로 확인 |
| 기존 동작 | 독립 메뉴 막대 항목의 실제 클릭·메뉴·접근성·16–32pt 렌더링, 설정 슬라이더 장거리 드래그 회귀 통과 |

실제 주 실행 루프 검사에서 Option+Tab 중복 이동을 발견해 창의 이벤트 경계에서 차단했다. 결과 목록의 빈 곳을 누를 때 입력 포커스가 빠지는 경로와 서로 다른 검색 실행이 단일 작업 슬롯에 막히는 경로도 수정했다. 일반 NSPredicate 평가와 달리 Spotlight가 자식 하나인 AND를 거절하는 사례는 실제 OS 조회로 재현하고 회귀 검사에 추가했다.

`docs/assets/switcher.png`는 합성 앱 목록을 표시한 실제 제품 뷰를 자체 렌더링한 이미지다. 사용자 파일명이나 화면 배경은 포함하지 않는다.

## 한계

검색 범위와 가용성은 Spotlight 색인·제외 설정·파일 접근 권한에 따른다. 시스템 Spotlight 창의 계산·추천·액션과 동일한 결과 순서는 제공하지 않는다. 한글 조합 검사는 AppKit의 marked text 경계를 확인하며 모든 서드파티 입력기의 실사용을 대신하지 않는다. 외부 사용자 문서를 실제로 여는 검사는 수행하지 않았다.

이 기능은 `main`의 미배포 변경이다. 공개된 v1.0.3 태그와 파일은 수정하지 않았다.
