# 구현 순서와 검증 기준

작성: 2026-09-28. 이 문서는 구현 계획이며 아래 기능/시험은 아직 수행하지 않았다.

## 0. 위험한 OS 동작부터 확인

전체 Xcode 경로를 준비한 뒤 작은 AppKit 프로토타입을 만든다. 제품 전체 구현보다 아래 두 실험을 먼저 끝낸다.

### A. 단일 status item과 키보드

고정 아이콘 6개를 한 항목에 그리고, 설정 drag로 순서를 바꾼 뒤 저장/재시작한다. Option+Tab 패널과 Enter/Esc까지 연결한다.

통과 기준:

- 로그인 직후와 재실행에서 중간 빈 슬롯이 없다.
- 두 화면 사이 활성 화면을 바꿔도 아이콘 색상/종횡비/간격이 깨지지 않는다.
- Light/Dark, 대비 증가, 투명도 감소, 1x/2x 외부 모니터에서 보인다.
- Command+drag는 전체 항목을 이동하며 이후 앱 이벤트가 위치를 초기화하지 않는다.
- 전역 단축키 한 입력이 정확히 한 번 이동하고, Enter가 다른 앱에 전달되지 않는다.
- 패널 취소 시 기존 작업 앱의 포커스가 유지/복귀한다.
- VoiceOver에서 각 아이콘 이름과 실행 동작을 구분할 수 있다.

실패하면 우선 strip rendering 방식을 수정한다. 단일 항목으로 요구를 충족할 수 없으면 독립 항목 또는 compact UI의 구체적 차이를 문서화하고 구조 결정을 다시 검토한다. 다중 화면 문제를 무시하고 다음 단계로 넘어가지 않는다.

### B. 비활성 화면의 색상 재현

[사용자 제공 이미지](assets/inactive-display-reference.png)를 기준으로, 기존 방식과 표준 `NSStatusBarButton.image` 경로를 비교한다. 강제 appearance 없음/있음, full-color/template, 1x/2x, 서로 다른 배경의 두 화면을 조합한다.

통과 기준:

- Safari/Finder/Notion/VS Code 등 서로 다른 아이콘의 색이 비활성 화면에서도 식별된다.
- 흰색으로 번짐, 청록색 편향, 임의 배경 사각형이 추가되지 않는다.
- 시스템이 적용하는 정상적인 비활성 dimming과 접근성 대비 설정은 유지한다.
- 색상 개선과 아이콘별 클릭·우클릭·VoiceOver 지원을 동시에 만족한다.

새 앱의 실행 화면 지정과 타 앱 창 이동은 사용자 요청으로 제외한다. 관련 권한·AX 모듈·창 배치 테스트를 첫 버전에 추가하지 않는다.

## 1. 핵심 상태와 저장

`DockCore`, `Persistence`, `WorkspaceMonitor`, `AppStore`를 구현한다. 앱 ID/프로세스 ID, 상대 순서 불변식, 중복 제거, 설정 저장/복구를 먼저 고정한다.

의미 있는 정책 테스트:

- 같은 이벤트 재전달, launch/activation/terminate 순서 차이, accessory 활성화.
- 고정 앱 재실행, 비고정 앱 재등장, 같은 bundle ID의 두 설치 경로.
- 경로 이동, stale bookmark, 앱 삭제, PID 재사용.
- 순서 변경 후 종료를 기다리지 않고 재시작해도 저장 순서 복원.
- 손상 JSON, 미래 schema, 저장 실패, 연속 저장 revision 역전 방지.
- 수백 개 이벤트를 재생해도 중복 ID, 순서 변동, 무한 history 증가 없음.

완료 조건: UI 없는 테스트에서 상태/순서를 검증하고, 실제 앱 이벤트와 fixture event replay가 같은 정책을 사용한다.

## 2. 사용 가능한 첫 버전

아이콘 클릭/우클릭, 고정/제외/순서 변경, overflow, compact 모드, 설정 화면, 로그인 시작을 연결한다. 실행 중 표시를 위한 뷰나 빈 공간은 만들지 않는다.

launch/activation pipeline과 단축키 세션을 제품 상태에 연결한다. 단축키를 변경하거나 등록하지 못했을 때도 마우스로 앱과 설정에 접근할 수 있어야 한다.

완료 조건: 아래 요구사항 표 전체 통과. UI 자동화만으로 판단할 수 없는 실제 외관/Spaces 항목은 실기기 기록을 남긴다.

## 3. 성능·복구·배포

Release arm64에서 signpost와 Instruments로 기준선을 만든다. 설정/패널 반복 생성, 잠자기/깨우기, 디스플레이 분리/연결을 포함한다. 새 구현과 같은 조건으로 기존 앱도 측정할 수 있을 때만 성능 개선 배수를 말한다.

- `file`/`lipo -archs`로 앱과 포함된 실행 코드의 arm64 확인.
- idle CPU, physical footprint, launch 전달 지연, render 지연을 분리 측정.
- 최소 지원 macOS와 배포 대상 정식 macOS에서 검증. 현재 사용자 환경 macOS 27.0은 별도 행으로 기록.
- 단일 화면/노치 + 외부 화면/서로 다른 배율/화면 위아래 배치/주 화면 변경 검증.
- “디스플레이마다 개별 Spaces” 켬/끔, fullscreen, Stage Manager, 다른 메뉴 막대 관리 앱 유무 검증.
- 서명·공증·staple 후 깨끗한 사용자 계정에서 설치/로그인 시작 검증.
- Sparkle 도입 후 업데이트 전후 설정·로그인 등록의 연속성 확인.

CI는 pure tests, app build, strict concurrency diagnostics, fixture 통합 검증을 담당한다. 물리적 다중 디스플레이 외관 검증은 CI로 대체하지 않는다. OS/Xcode runner 버전은 명시적으로 고정하고 변경 때 회귀 검증한다.

## 요구사항별 출시 조건

| ID | 사용자 요구 | 통과 조건 |
| --- | --- | --- |
| R1 | 순서 고정 | 앱 활성화 100회, 실행/종료, 재부팅, 설정 저장 후에도 기존 앱 상대 순서 유지 |
| R2 | 중간 padding 제거 | 0/1/6/overflow 개수와 로그인 초기화에서 예약 빈 슬롯·임의 구분선 없음 |
| R3 | 다중 화면 외관 | 양 화면 활성/비활성 전환 시 색상·배율·간격 정상. 시스템 dimming은 유지 |
| R4 | 실행 중 표시 제외 | 메뉴 막대에 점·밑줄·배지 및 이를 위한 예약 공간 없음 |
| R5 | 단축키 | Option+Tab 순환, Shift 역순, Enter 1회 실행, Esc 취소, 선택 중 목록 안정 |
| R6 | 기본 실행 동작 | 기존 앱은 활성화, 종료된 앱은 실행. 앱의 창 위치를 직접 변경하지 않음 |
| R7 | 지연/오류 복구 | 실행 오류/단축키 충돌/화면 분리에도 설정 접근 가능. 중복 실행과 무한 재시도 없음 |

## 미확정 항목의 처리

구현을 막는 추가 제품 질문은 없다. 아래는 테스트에서 결정할 구현 항목이다.

- 단일 strip의 표준 버튼 hosting 방식과 VoiceOver 노출 방법.
- nonactivating panel의 지원 OS별 포커스 동작.
- icon cache, 표시 개수의 초기 수치 조정.
- 실제 Xcode 버전, app bundle ID, 서명 팀, 배포 URL.

기능을 축소해야 할 만큼 OS 제약이 발견되면 재현 결과와 선택지를 남기고 제품 결정을 다시 논의한다. 현재 설계 문서는 구현·성능 검증이 끝났다는 증거가 아니다.
