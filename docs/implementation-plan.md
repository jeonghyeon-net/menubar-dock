## 자동 검증

1.0.1 테스트는 도메인 16개, 저장소 20개, 플랫폼 17개, 단축키 15개, 앱 조립/업데이트/UI 27개로 구성하며, 총 95개가 로컬에서 모두 통과했다. 별도 AppKit 주 실행 루프에서 독립 메뉴 막대 버튼 8개의 실제 마우스 이벤트 전달도 검증했다. 앱 테스트에는 실제 AppKit control/responder를 사용하며 다른 사용자 앱을 실행하거나 종료하지 않는다.

| 검증 | 명령 / 확인 내용 |
| --- | --- |
| Swift 6 빌드 | `swift build -Xswiftc -warnings-as-errors` |
| 테스트 | `./scripts/test.sh` |
| Release arm64 | `./scripts/build-app.sh`, `file`, `lipo -verify_arch arm64` |
| 번들 | `MenuBarDock --self-test`: ID, LSUIElement, 아이콘, 기본 설정 |
| 실제 수명 | `./scripts/smoke-test.sh`: 20초 안에 시작 → 설정 저장 → 정상 종료 |
| 서명 | `codesign --verify --strict` (로컬은 ad-hoc) |
| 배포 이미지 | `hdiutil verify`, SHA-256, ZIP/DMG 생성 |
| 의존성 | `otool -L`: 시스템 프레임워크·Swift 런타임만 사용 |

Command Line Tools에 존재하지 않는 Developer 하위 framework 경로를 검색하는 linker warning이 있다. Swift 코드 경고나 누락된 런타임 의존성과 구별한다. 현재 번들 검증과 실제 실행은 통과했다.

통합 실행에서 `.terminateLater`의 modal 실행 루프가 MainActor 저장 continuation을 막는 현상을 재현했다. 저장은 detached task에서 actor로 전달하고, 완료는 modal/common 실행 루프에 전달해 `reply(toApplicationShouldTerminate:)`를 호출한다. 종료 요청을 취소했다가 다시 종료하는 우회 없이 정상 종료·로그아웃 응답 계약을 유지한다. 실제 프로세스 검사로 회귀를 잡는다.

CLI Swift Testing에서 NSButton.performClick의 중첩 루프가 테스트 프로세스를 조기 종료하는 현상도 재현했다. 테스트는 실제 target/action과 responder를 직접 사용하도록 고쳤고 모든 suite의 완료 요약까지 확인한다. GitHub의 기본 Bash 3에서 빈 배열+set -u가 실패하는 문제도 분기 실행으로 해결했다.

## 실제 UI 확인

macOS 27.0 / Swift 6.4 / Apple Silicon 환경에서 설정 창의 앱 목록과 단축키 화면을 직접 관찰했다. 앱 메뉴에서 선택 패널을 열고 방향키 이동·Enter 확정·설정 복귀를 확인했다. 표준 네이티브 메뉴, 앱 아이콘, 한국어 레이블, 접근성 트리를 확인했다. 실제 파일 선택에서 계산기 앱 추가·고정·위로 이동을 확인했다. 목록 제거에서 드러난 Swift inout 중첩 접근 충돌을 수정하고, 실제 ApplicationController에 명령을 전달하는 회귀 테스트를 추가했다.

자동화 도구의 대상 앱 키 입력과 실제 하드웨어 전역 단축키는 별도다. Option+Tab의 실제 하드웨어 입력은 사용자 확인 항목으로 남긴다. Carbon 독점 등록으로 다른 앱과의 조합 충돌을 오류로 알리고, 단축키 서비스의 등록·롤백·반복·취소는 테스트한다.

## 검증하지 않았다고 명시하는 범위

- 물리적 두 디스플레이의 비활성 색상/배율, 연결·분리, 주 화면 변경.
- macOS 14–26 각 버전의 실기기, Spaces/fullscreen/Stage Manager의 모든 조합.
- 실제 재부팅 후 SMAppService 로그인 시작과 깨끗한 계정 설치.
- Developer ID 인증서와 Apple 공증. 현재 인증서가 없어 로컬 ad-hoc 서명으로 검사한다.
- 장시간 Instruments 에너지/메모리 측정과 기존 앱 대비 성능 비교.

이 항목을 통과한 것으로 꾸미거나 단일 화면·단위 테스트로 대체하지 않는다. 배포 절차는 [releasing.md](releasing.md), 기본 사용 방법은 [user-guide.md](user-guide.md)에 있다.

## 1.0.0 검증의 한계와 1.0.1 수정

이전 완료 보고의 테스트는 메뉴 막대의 실제 마우스 입력을 검증하지 못했다. 합성 이미지 한 장을 버튼에 넣고 이벤트 좌표로 앱을 선택하는 구현은 사용자가 기대한 개별 버튼 동작을 제공하지 못했다. 이 경로와 단일 상태 항목 안의 자식 버튼 구현을 모두 폐기하고 앱별 NSStatusItem으로 재작성했다. 이전의 테스트 통과를 이 결함이 없다는 근거로 사용하지 않는다.

- 앱마다 독립된 시스템 메뉴 막대 항목이 있고 표준 leftMouseUp action을 사용한다.
- 상단은 앱 아이콘만 표시한다. 앱 재실행과 선택 패널의 톱니 버튼으로 설정에 접근한다.
- 설정은 너비 520pt와 탭별 높이 230–360pt, 34pt 앱 행, 경로 tooltip, 고정·표시 열, 직접 추가·제거·이동 조작으로 정리했다.
- 선택 패널은 116pt로 줄이고 재질 마스크로 모서리의 흰색 사각 잔상을 수정했다.
- 요청하지 않은 GitHub CI는 제거하고 저장소 Actions도 비활성화했다. 검증은 로컬 명령으로 유지한다.

수정 검증의 상세 결과는 [1.0.1 기록](verification/1.0.1.md)에 남긴다.

## 1.0.0의 짧은 대기 상태 측정

macOS 27.0의 Release 앱, 설정 창을 연 상태에서 top 3회/2초 간격으로 측정했다. 변경 전에는 appearance KVO와 이미지 재생성이 반복되어 CPU 43.1–48.3%가 관찰됐다. 표시 상태 동등성 검사 적용 후 연속 관측값은 CPU 0.0%, 메모리 약 33MiB였다. 이는 이번 구현의 렌더링 결함 전후를 확인한 짧은 관측이며, 장시간 에너지 벤치마크나 기존 EthanSK 앱과의 비교 수치는 아니다.

## 1.0.2 설정 접근·크기·자동 감지 검증

우클릭과 Control-클릭 메뉴에서 설정 및 표시 탭으로 직접 이동한다. 기본 아이콘은 24pt로 보정하고 실제 버튼 영역 안으로 제한한다. 저장된 동일 설치 중복은 첫 ID·순서와 사용자 정책을 보존하면서 합친다.

전체 105개 테스트, 실제 AppKit 좌우 클릭·메뉴 tracking·접근성 press, Release 앱의 설정 조절·기본값 복원·순서 보존, arm64 앱·ZIP·DMG 검사를 통과했다. 구체적인 확인 범위와 한계는 [1.0.2 검증 기록](verification/1.0.2.md)에 있다.

## 1.0.3 설정·아이콘·Dock 목록 수정

설정을 탭·카드 없는 단일 창으로 통합했다. 이전 이미지로 결정된 버튼 높이를 새 이미지의 상한으로 쓰던 순환 제한을 제거하고, 실제 16–32pt 렌더링을 확인한다. 추가 간격은 기본 0pt이며 macOS의 독립 상태 항목 여백과 구분한다. 슬라이더는 드래그 중 모델의 반올림 값을 손잡이에 되쓰지 않는다.

macOS Dock 고정 앱과 Finder를 자동 감지한다. 수동 가져오기 버튼은 없으며 사용자 순서·고정 해제·제외를 유지한다. `−`는 설정 행까지 제거하고 삭제 기록은 별도로 저장하여 자동 감지로 되살아나지 않게 한다. `+`로 명시적으로 다시 추가할 수 있다.
